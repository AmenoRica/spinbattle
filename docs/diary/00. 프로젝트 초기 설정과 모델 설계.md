### CustomUser 모델

Django의 `AbstractUser`를 상속하여 `bio` 필드를 추가했다. `AUTH_USER_MODEL = "accounts.CustomUser"`로 설정하여 프로젝트 전체에서 커스텀 유저 모델을 사용한다.

```python
class CustomUser(AbstractUser):
    bio = models.TextField(blank=True)
```

### SpinImage 모델

이미지 업로드 시 자동으로 계산되는 필드들이 핵심이다.

```python
class SpinImage(models.Model):
    user = models.ForeignKey(CustomUser, related_name="spin_images")
    name = models.CharField(max_length=30)
    image = models.ImageField(upload_to="spins/%Y/%m/%d/")
    hash = models.CharField(max_length=64, unique=True, editable=False)   # SHA-256
    spin_type = models.CharField(max_length=10, editable=False)         # 자동 계산
    wins = models.PositiveIntegerField(default=0)
    losses = models.PositiveIntegerField(default=0)
    battle_score = models.IntegerField(default=1000)                    # ELO 레이팅
```

**핵심 설계 결정**:

- `hash`는 이미지 바이트의 SHA-256 해시다. 같은 이미지를 업로드해도 동일한 스탯이 나오도록 보장한다. `save()`에서 자동 계산된다.
- `spin_type`은 이미지의 평균 색상에서 자동으로 할당된다. `save()`에서 `compute_type_from_image()`를 호출하여 계산한다.
- `battle_score`는 ELO 레이팅의 초기값 1000으로 시작한다.
- `MAX_PER_USER = 3`으로 유저당 최대 3개까지만 업로드할 수 있게 제한했다. `clean()` 메서드에서 검증한다.
- `MAX_SIZE_BYTES = 5 * 1024 * 1024` (5MB)로 이미지 크기를 제한했다.

## 어떤 문제를 겪었나

### 1. Pillow 의존성 누락

`battle/types.py`에서 `Pillow`를 사용해 이미지를 열고 색상을 분석하는데, `requirements.txt`에 `Pillow`가 누락되어 있었다. 배포 환경에서 `ModuleNotFoundError`가 발생할 수 있어 추가했다.

### 2. CustomUser 모델의 user 접근

`SpinImage.clean()`에서 `self.user`에 접근할 때, 인스턴스가 아직 저장되지 않은 상태에서는 `DoesNotExist` 예외가 발생할 수 있다. 이를 방지하기 위해 `try-except`로 감싸는 처리가 필요했다.

### 3. 단일 앱 구조

`battle/` 패키지는 Django 앱이 아닌 순수 Python 패키지로 설계했다. `INSTALLED_APPS`에는 `accounts`만 등록하고, `battle/`은 모델이 없는 독립적인 게임 로직 모듈로 유지했다. 이렇게 하면 전투 엔진을 Django 없이도 테스트할 수 있다.

## 배운 점

- Django 커스텀 유저 모델은 프로젝트 시작 시점에 정의하는 것이 중요하다. 중간에 바꾸면 마이그레이션이 매우 복잡해진다.
- `ImageField`를 사용할 때는 반드시 `Pillow`가 설치되어 있어야 한다. `requirements.txt`에 명시적으로 적어두지 않으면 로컬에서는 되는데 배포에서 깨지는 현상이 발생한다.
- 모델의 `save()`와 `clean()`에서 자동 계산 필드를 다룰 때는 인스턴스의 저장 상태(새 인스턴스인지 기존인지)를 항상 염두에 두어야 한다.
