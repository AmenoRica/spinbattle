## 목표

이미지 해시에서 스탯을 계산하고, 속성 시스템과 상성을 정의하며, 한국어 조사를 자동으로 선택하는 함수를 만든다. 전투 메시지와 랜덤 이벤트 텍스트도 다국어로 준비한다.

## 무엇을 만들었나

### 스탯 계산 (`battle/stats.py`)

SHA-256 해시를 6등분하여 각 스탯을 [10, 100] 범위의 정수로 변환한다.

```python
def compute_stats(hash_str):
    # 해시를 6개 청크로 분할 → 각각 [10, 100] 범위의 정수
    stats = {}
    for i, key in enumerate(STAT_KEYS):  # speed, acceleration, luck, stamina, attack, defense
        chunk = hash_str[i*11 : (i+1)*11]
        value = 10 + (int(chunk, 16) % 91)
        stats[key] = value
    return stats
```

**등급 시스템**: 스탯 값에 따라 S+/S/S-, A+/A/A-, B+/B/B-, C+/C/C- 등급을 부여하고, 등급별 색상골드, 레드, 블루, 그레이)을 반환한다.

**다국어**: `get_stat_names(lang)`으로 ko/ja/en 스탯 이름을 반환한다.

### 속성 시스템 (`battle/types.py`)

10개 속성과 각 속성의 한국어/일본어/영어 이름, HEX 색상을 정의했다.

```
fire(불꽃), water(물), grass(풀), electric(전기), ice(얼음),
steel(강철), dragon(드래곤), dark(악), psychic(에스퍼), fighting(격투)
```

**상성 테이블**: 각 속성이 2개의 유리한 상대 속성을 가진다. 공격 시 유리하면 1.2배, 불리하면 약 0.833배(1/1.2), 그 외 1.0배.

**이미지 → 속성**: `compute_type_from_image()`에서 PIL로 이미지를 50×50으로 축소한 뒤 평균 RGB를 계산하고, HSV 변환 후 색상/채도/명도 기준으로 속성을 할당한다.

### 조사 함수 (`battle/josa.py`)

한국어의 받침 여부에 따라 조사를 선택하는 함수를 만들었다.

```python
def josa_ko(name, pair):
    # pair = ("은", "는") 또는 ("이", "가")
    last = ord(name[-1])
    if (last - 0xAC00) % 28 != 0:  # 받침 있음 → pair[0]
        return name + pair[0]
    return name + pair[1]            # 받침 없음 → pair[1]
```

일본어는 항상 고정 조사(は, が), 영어는 공백을 사용하도록 `josa_ja`, `josa_en`을 준비했다.

### 전투 메시지 (`battle/messages.py`)

전투 로그에 출력되는 19개 메시지 템플릿을 ko/ja/en 3개국어로 정의했다. 예:

```python
MESSAGES = {
    "ko": {
        "attack": "{attacker}의 돌진! {damage:.1f} 데미지!{crit_text}{type_text} ({defender_josa} 속도 {old:.1f} → {new:.1f})",
        ...
    },
    "ja": { ... },
    "en": { ... },
}
```

`{name_josa}` 등의 플레이스홀더에 `josa_ko/ja/en` 함수의 결과를 채워 넣는 방식이다.

### 랜덤 이벤트 (`battle/events.py`)

긍정 이벤트 5종, 부정 이벤트 4종을 정의했다. 각 이벤트는 가중치, 효과 종류, 값, 조사 쌍, 그리고 3개국어 텍스트(name, message, log, float_text)를 가진다.

## 어떤 문제를 겪었나

### 1. 조사 시스템의 다국어 확장

처음에는 한국어 조사만 생각했지만, 일본어와 영어에서도 문장을 자연스럽게 만들어야 했다. 일본어는 조사 선택 문제가 없어 항상 고정 조사(は, が)를 사용하도록 했고, 영어는 단순히 공백을 넣도록 했다. 이 세 가지 조사 함수를 `JOSA` 딕셔너리에 모아두어 전투 엔진에서 `lang` 파라미터만으로 자동 선택되게 했다.

### 2. 이벤트 조사 데이터의 구조

랜덤 이벤트마다 팽이 이름 뒤에 붙는 조사가 다르다(은/는, 이/가, 또는 조사 없음). 이를 `EVENT_DATA`에서 각 이벤트마다 조사 쌍을 지정하도록 했다. 예: `("dragon_dance", "speed_recover_pct", 15, 0.15, ("은", "는"), ("は",), ("",))` — 한국어는 은/는 쌍, 일본어는 고정 は, 영어는 빈 문자열.

### 3. 스탯 분포의 균형

해시의 특정 청크가 항상 비슷한 범위에 몰리는 문제를 방지하기 위해, `int(chunk, 16) % 91 + 10` 공식을 사용했다. 이렇게 하면 해시의 각 부분이 고르게 [10, 100] 범위에 분포하게 된다.

## 배운 점

- 게임 로직을 Django와 분리된 순수 Python 패키지(`battle/`)에 두면, Django 서버 없이도 `python -c "from battle.stats import compute_stats"`로 직접 테스트할 수 있어 개발 속도가 빨라진다.
- 다국어 지원을 처음부터 설계하는 것이 나중에 추가하는 것보다 훨씬 쉽다. 메시지 템플릿을 dict 구조로 관리하면 언어 추가가 거의 기계적인 작업이 된다.
- 한국어 조사 처리는 받침 여부 판별만으로 충분하지 않다. "이/가"와 "은/는"처럼 조사 쌍이 여러 개 있고, 이벤트마다 다른 조사 쌍이 필요할 수 있다.
