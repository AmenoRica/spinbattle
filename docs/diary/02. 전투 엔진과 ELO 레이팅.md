# 02. 전투 엔진과 ELO 레이팅

## 목표

턴제 전투 시뮬레이션 엔진을 구현하고, ELO 레이팅으로 랭크 대전의 승패를 반영한다.

---

## 무엇을 만들었나

### 전투 엔진 (`battle/engine.py`)

`simulate()` 함수는 두 팽이의 해시, `random.Random` 인스턴스, 이름, 속성, 언어를 받아 전투 로그를 반환한다.

**턴 구조 (최대 25턴)**:

1. **가속 이벤트**: 기본 15% + 행운×0.55% 확률로 가속 발동. 성공 시 속도가 `5 × √(가속)` 증가. 실패 시 로그만 출력.
2. **선공 판정**: 속도 ± 행운×0.5의 랜덤 범위로 먼저 공격할 팽이 결정.
3. **공격 페이즈**: 선공 팽이가 공격 → 피격 팽이가 살아있으면 반격.
4. **속도 ≤ 0 체크**: 어느 쪽이든 속도가 0 이하가 되면 전투 종료.
5. **랜덤 이벤트**: 기본 5% + 행운×0.25% 확률로 발동. 행운이 높을수록 긍정 이벤트 발생 확률이 높음.
6. **감속**: `3 × (100/지구력) × (1 + (턴-1) × 0.08)` 만큼 속도 감소. 턴이 갈수록 감속량이 커진다.

**데미지 공식**:

```
base_damage = (속도 × 공격력) / 500
× 크리티컬 배율 (기본 1.5 + 가속/200, 5% + 행운×0.3% 확률)
× 속성 상성 배율 (1.2 / 0.833 / 1.0)
방어 감소율 = 방어 / (방어 + 100)
최종 데미지 = base_damage × (1 - 방어 감소율)
```

**기합의 머리띠**: 속도가 0이 되어도 한 번 버텨주는 시스템. `ENDURE_THRESHOLD = 10`으로 설정하여 버틸 시 속도가 10으로 복원된다.

**RNG 주입**: `random.Random` 인스턴스를 외부에서 주입하여 같은 시드로 같은 결과를 재현할 수 있다.

### ELO 레이팅 (`battle/rating.py`)

```python
def expected_score(rating_a, rating_b):
    return 1 / (1 + 10 ** ((rating_b - rating_a) / 400))

def compute_new_ratings(rating_a, rating_b, result):
    # result: "a", "b", "draw"
    K = 32
    ea = expected_score(rating_a, rating_b)
    eb = expected_score(rating_a, rating_b)  # 실제로는 1 - ea
    if result == "a":
        sa, sb = 1, 0
    elif result == "b":
        sa, sb = 0, 1
    else:
        sa, sb = 0.5, 0.5
    new_a = rating_a + K * (sa - ea)
    new_b = rating_b + K * (sb - eb)
    return round(new_a), round(new_b)
```

K=32의 표준 ELO를 사용한다. 초기 레이팅은 1000점.

### 랭크 매칭

상대의 팽이를 선택할 때 점수 차이에 반비례하는 가중치를 부여하여 가까운 점수의 상대와 더 자주 매칭되도록 했다.

```python
weight = 1.0 / (1.0 + abs(c.battle_score - my_score) / 200.0)
```

## 어떤 문제를 겪었나

### 1. RNG 재현성

전투 결과를 디버깅하거나 리플레이할 때 같은 결과가 나와야 했다. `random.Random()`을 `simulate()` 외부에서 생성하여 주입하는 방식을 채택했다. 뷰에서는 `rng = random.Random()`으로 새 인스턴스를 만들어 전달한다.

### 2. 조사 함수와 메시지 템플릿의 결합

전투 메시지에서 `{name_josa}` 같은 플레이스홀더에 조사가 적용된 이름을 넣어야 했다. 이를 위해 `josa_fn(name, pair)` 패턴을 사용했다. 예: `josa_ko("불꽃", ("은", "는"))` → `"불꽃은"`. `name_josa` 플레이스홀더는 전투 엔진에서 `josa_fn`을 호출하여 채워진다.

### 3. 반격 불가 처리

공격받은 팽이의 속도가 이미 0이면 반격할 수 없다. 이때 "속도가 0이 되어 반격할 수 없다"는 메시지를 출력해야 했는데, 처음에는 이 케이스를 누락했다가 테스트하다 발견하여 `counter_fail` 이펙트로 추가했다.

### 4. `Coalesce` import

데이터베이스 쿼리에서 `Sum`과 `Coalesce`를 사용할 때, `Coalesce`를 `django.db.models`에서 import하려고 하면 에러가 발생한다. `django.db.models.functions`에서 import해야 한다. 이 사실을 AGENTS.md에 명시해두었다.

## 배운 점

- 게임 밸런스 상수(데미지 공식의 500, 크리티컬 확률, 감속 계수 등)를 파일 상단에 모아두면 튜닝하기 편하다. 실제로 여러 번 값을 조정하며 밸런스를 맞췄다.
- ELO 레이팅은 구현이 간단하지만, 무승부 처리와 K-factor 선택이 중요하다. K=32는 체스에서 많이 쓰는 값이고, 초반에는 점수 변화가 크고 나중엔 안정되는 특성이 게임에도 적합하다.
- 전투 엔진을 순수 함수로 유지하면 테스트와 디버깅이 쉽다. Django 모델이나 데이터베이스에 의존하지 않기 때문에 커맨드라인에서 직접 실행해볼 수 있다.
