# 03. 기본 화면과 CRUD

## 목표

사용자가 이미지를 업로드하고, 팽이의 스탯을 확인하고, 유저 목록을 볼 수 있는 기본 화면을 만든다.

---

## 무엇을 만들었나

### 페이지 구성

| URL | 템플릿 | 내용 |
|-----|--------|------|
| `/` | `home.html` | 랜딩 페이지, "시작하기" 버튼 |
| `/accounts/profile/` | `accounts/profile.html` | 내 프로필 수정 + 내 팽이 목록 |
| `/accounts/upload/` | `accounts/upload.html` | 이미지 업로드 (1인당 최대 3개) |
| `/accounts/users/` | `user_list.html` | 유저 목록, 대전 점수 합 순 정렬 |
| `/accounts/spins/<pk>/` | `spin_detail.html` | 팽이 상세, 육각 레이더, 친선 대전 버튼 |
| `/accounts/signup/` | `accounts/register.html` | 회원가입 |
| `/accounts/login/` | `registration/login.html` | 로그인 |

### 핵심 뷰

- **`upload_image`**: `SpinImageForm`으로 이름+이미지를 받고, `save(commit=False)` 후 user를 세팅, `full_clean()`으로 검증(5MB 제한, 3개 제한) 후 저장.
- **`spin_detail`**: 서버 사이드에서 SVG 육각 레이더를 계산하여 템플릿에 전달. `_hex_point()`, `_hex_points_str()` 헬퍼로 격자, 스포크, 스탯 폴리곤, 라벨 좌표를 생성한다.
- **`user_list`**: `Sum` + `Coalesce`로 유저별 총 대전 점수/승/패를 어노테이션하여 정렬.

### SVG 육각 레이더 차트

서버에서 6개 스탯을 정규화(0~1)하여 6각형 폴리곤 좌표를 계산하고, 템플릿에서 SVG로 렌더링한다.

```python
cx, cy, max_r = 150, 150, 110
# 4개 격자 고리 (25%, 50%, 75%, 100%)
grid_rings = [_hex_points_str(cx, cy, max_r * p) for p in (0.25, 0.5, 0.75, 1.0)]
# 스탯 폴리곤
stat_values = [stats[k] / 100.0 for k in STAT_KEYS]
stat_polygon = " ".join(f"{x:.1f},{y:.1f}" for x, y in [_hex_point(cx, cy, max_r * v, i) for i, v in enumerate(stat_values)])
```

### 폼

4개의 ModelForm을 만들었다:
- `CustomUserCreationForm`: 회원가입 (username, email, password1, password2)
- `CustomUserChangeForm`: 프로필 수정 (username, email, bio)
- `SpinImageForm`: 업로드 (name, image)
- `SpinImageRenameForm`: 이름 변경 (name, only)

## 어떤 문제를 겪었나

### 1. `base.html` 템플릿 구조

모든 페이지가 `base.html`을 확장하도록 설계했는데, 전투 페이지(`battle_friendly.html`)는 전체화면 레이아웃이 필요해서 `base.html`을 확장하지 않고 독립형 HTML로 만들었다. 이 때문에 전투 페이지에는 별도로 CSS, JS, i18n 설정을 해야 하는 문제가 있었다.

### 2. 이미지 업로드 검증

`SpinImage.clean()`에서 `self.user`에 접근할 때 인스턴스가 아직 저장되지 않은 상태면 `RelatedObjectDoesNotExist` 예외가 발생한다. `try-except`로 감싸서 처리했다.

### 3. 육각 레이더의 라벨 위치

스탯 라벨을 각 꼭짓점에서 바깥쪽으로 22px 떨어진 위치에 배치해야 했는데, `max_r + 22` 거리의 좌표를 계산할 때 위쪽 라벨이 잘리는 문제가 있었다. SVG `viewBox`를 충분히 크게(300×300) 설정하여 해결했다.

### 4. 비동기 이미지 타입 계산

`compute_type_from_image()`에서 이미지를 열고 HSV로 변환한 후 `image_field.seek(0)`로 파일 포인터를 원래 위치로 되돌리지 않으면, 이후 Django가 파일을 읽을 때 빈 데이터가 되는 문제가 있었다. 반드시 `seek(0)`을 호출해야 한다.

---

## 배운 점

- Django의 `AbstractUser`를 확장할 때는 프로젝트 초기에 하는 것이 중요하다. 나중에 바꾸면 기존 마이그레이션과 충돌한다.
- SVG를 서버 사이드에서 렌더링하면 JavaScript 라이브러리 없이도 인터랙티브 차트를 만들 수 있다. 하지만 좌표 계산이 복잡할 수 있으니 헬퍼 함수를 미리 만들어두는 것이 좋다.
- `ImageField`를 다룰 때는 항상 파일 포인터 위치를 고려해야 한다. `seek(0)`을 잊으면 이미지 저장이 실패하거나 데이터가 손상될 수 있다.
