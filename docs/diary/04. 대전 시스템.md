# 04. 대전 시스템

## 목표

친선 대전과 랭크 대전 기능을 구현하고, 전투 결과를 localStorage에 저장하여 배틀 페이지에서 재생하는 흐름을 완성한다.

---

## 무엇을 만들었나

### 대전 흐름

1. 유저가 팽이 상세 페이지에서 "친선 대전" 버튼을 누르거나, 상단바에서 "랭크 대전" 버튼을 누른다.
2. 모달에서 내 팽이를 선택한다.
3. JavaScript가 `fetch()`로 POST 요청을 보낸다.
4. 서버가 전투를 시뮬레이션하여 JSON 결과를 반환한다.
5. JSON을 `localStorage('battle_data')`에 저장하고 `/battle/` 페이지로 이동한다.
6. 배틀 페이지에서 localStorage를 읽어 전투를 재생한다.

### 친선 대전 (`friendly_battle`)

- 내 팽이끼리도 대전 가능. 단, 같은 팽이끼리는 서버에서 차단(`.same pk` 체크).
- 랭크 점수, 승패 기록에 영향 없음.
- 결과 JSON에 `mode: "friendly"` 포함.

### 랭크 대전 (`ranked_battle`)

- 상대 팽이를 점수 근접 가중 랜덤으로 자동 선택.
- ELO 레이팅 업데이트, 승패 기록 갱신.
- 결과 JSON에 `mode: "ranked"`, `old_score`, `new_score` 포함.
- 전투 종료 후 배틀 페이지에서 점수 변동 표시.

### 모달 UI

- **친선 대전 모달**: `spin_detail.html`에 배치. 내 팽이 목록에서 현재 보는 팽이를 제외하고 선택.
- **랭크 대전 모달**: `base.html` 상단바에 배치. 내 팽이 목록에서 선택.

### 데이터 구조

전투 결과 JSON의 구조:

```json
{
  "mode": "friendly" | "ranked",
  "spin_a": { "name", "image_url", "spin_type", "spin_type_name", "spin_type_color", "old_score", "new_score" },
  "spin_b": { ... },
  "log": [
    { "text": "전투 로그 텍스트", "effects": [{ "type": "attack", "attacker": "a", ... }] },
    ...
  ]
}
```

---

## 어떤 문제를 겪었나

### 1. 팽이 선택 모달의 소유권

친선 대전은 내 팽이끼리도 가능해야 하므로, `spin_detail.html`에서 상대방 팽이 페이지를 보면서 "내 팽이 중 어떤 것으로 싸울지" 선택하는 구조다. 처음에는 상대방 팽이 페이지에 있는 버튼이 어떤 팽이를 선택하는지 헷갈렸다. 결국 "내 팽이를 선택하세요" 모달에서 현재 보는 팽이를 제외하는 방식으로 해결했다.

### 2. 같은 팽이끼리 대전 차단

같은 팽이끼리 대전하면 결과가 항상 무승부에 가까워지고, 랭크 점수 조작이 가능해진다. 서버 측에서 `my_spin.pk == opp_spin.pk` 체크를 추가했다.

### 3. 랭크 대전의 매칭 로직

처음에는 단순 랜덤 선택을 고려했지만, 실력 차이가 너무 큰 매칭이 빈번하게 발생했다. 점수 차이에 반비례하는 가중치를 부여하여 비슷한 점수의 상대와 더 자주 매칭되도록 개선했다.

### 4. `battle_friendly.html`의 독립성

배틀 페이지는 전체화면 레이아웃이 필요해서 `base.html`을 확장하지 않는다. 이로 인해 nav bar, footer, 언어 선택기가 없고, i18n 태그를 수동으로 로드해야 한다. 나중에 `{% load i18n %}` 위치 때문에 템플릿 에러가 발생하기도 했다.

## 배운 점

- localStorage를 통한 데이터 전달은 간단하지만, 페이지 이동 후에도 데이터가 남아있으므로 주의해야 한다. 전투가 끝난 후에도 localStorage를 비우지 않아 "뒤로 가기"로 재접속하면 같은 전투가 재생된다.
- 랭크 대전은 공격자(요청자)와 수비자(선택된 상대)를 명확히 구분해야 한다. ELO 계산에서 result가 "a"(요청자 승)인지 "b"(상대 승)인지에 따라 점수 업데이트가 다르다.
- 전투 데이터는 JWT나 세션이 아닌 localStorage에 저장하므로, 클라이언트가 임의로 조작할 수 있다. 랭크 대전의 점수 업데이트는 서버에서만 수행하므로 안전하지만, 친선 대전의 결과는 클라이언트에서만 볼 수 있어 조작의 여지가 있다.
