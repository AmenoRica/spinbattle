# 06. 다국어(i18n) 시스템

## 목표

한국어, 일본어, 영어 3개국어를 지원한다. Django 템플릿, Python 전투 엔진, JavaScript 3계층 모두에 다국어를 적용한다.

---

## 무엇을 만들었나

### 3계층 다국어 아키텍처

| 계층 | 범위 | 방식 |
|------|------|------|
| Django 템플��릿 | 버튼, 라벨, 에러 메시지 | `{% trans %}`, `{% blocktrans %}`, `.po/.mo` 파일 |
| Python (전투 엔진) | 전투 로그, 속성명, 이벤트 텍스트 | `MESSAGES[lang]`, `EVENT_TEXT[lang]`, `STAT_NAMES[lang]` dict |
| JavaScript | 배틀 페이지 UI 문자열 | `BattleI18n` 객체 (템플릿에서 `{% trans %}`로 주입) |

### Django 설정

```python
# settings.py
USE_I18N = True
LANGUAGE_CODE = 'ko'
LANGUAGES = [('ko', '한국어'), ('ja', '日本語'), ('en', 'English')]
LOCALE_PATHS = [BASE_DIR / 'locale']
MIDDLEWARE = [..., 'django.middleware.locale.LocaleMiddleware', ...]
TEMPLATES[0]['OPTIONS']['context_processors'] = [
    ...,
    'django.template.context_processors.i18n',
]
```

`LocaleMiddleware`가 세션/쿠키/Accept-Language 헤더에서 언어를 감지하고, `i18n` 컨텍스트 프로세서가 `LANGUAGE_CODE`를 템플릿에 제공한다.

### `.po` 파일

`locale/{ko,ja,en}/LC_MESSAGES/django.po`에 약 50개의 번역 문자열을 정의했다. `makemessages`로 추출하고 `compilemessages`로 `.mo` 파일을 생성한다.

### 전투 엔진 i18n

`simulate()` 함수가 `lang` 파라미터를 받아 해당 언어의 메시지를 사용한다:

```python
def simulate(hash_a, hash_b, rng, name_a="A", name_b="B", type_a=None, type_b=None, lang="ko"):
    msgs = MESSAGES.get(lang, MESSAGES["ko"])
    josa_fn = JOSA.get(lang, JOSA["ko"])
    # ... 로그 생성 시 msgs["attack"].format(...) 사용
```

`get_language()`를 뷰에서 호출하여 `lang` 파라미터로 전달한다.

### JavaScript i18n

`battle_friendly.html`에서 Django 템플릿 태그로 `BattleI18n` 객체를 주입한다:

```html
<script>
window.BattleI18n = {
    noBattleData: "{% trans '전투 데이터가 없습니다.' %}",
    rankedBattle: "{% trans '랭크 대전' %}",
    friendlyBattle: "{% trans '친선 대전' %}",
    pts: "{% trans '점' %}",
    accel: "{% trans '가속!' %}",
    endure: "{% trans '인해!' %}",
    countdownGo: "{% trans '시작!' %}"
};
</script>
```

이 방식은 JavaScript 파일을 별도의 JSON 파일로 만들지 않고도 Django의 번역 시스템을 그대로 활용할 수 있다.

### 조사 시스템 다국어

한국어는 받침 여부에 따라 조사를 선택(은/는, 이/가), 일본어는 고정 조사(は, が), 영어는 공백을 사용한다:

```python
JOSA = {
    "ko": josa_ko,  # 받침 여부 판별
    "ja": josa_ja,  # 항상 고정 조사
    "en": josa_en,  # 공백
}
```

## 어떤 문제를 겪었나

### 1. `{% load i18n %}` 위치 에러

`battle_friendly.html`에서 `{% load i18n %}`가 `{% trans %}` 태그보다 뒤에 있어서 `TemplateSyntaxError`가 발생했다. Django 템플릿은 `{% load %}`가 같은 템플릿 파일에서 태그를 사용하기 전에 선언되어야 한다. `{% load i18n static %}`을 파일 최상단(Doctype 이전)으로 옮겨서 해결했다.

### 2. `.po` 파일의 fuzzy 마커

`makemessages`를 실행할 때마다 기존 번역과 유사한 문자열에 `#, fuzzy` 마커가 자동으로 붙었다. fuzzy 마커가 있으면 Django가 번역을 무시하고 원문(msgid)을 그대로 출력한다. "시작!"이 항상 한국어로만 표시되는 문제의 원인이었다. 모든 `.po` 파일에서 fuzzy 마커와 `#|` 참조 줄을 제거하고 `compilemessages`를 다시 실행하여 해결했다.

### 3. 전투 페이지의 독립성

`battle_friendly.html`은 `base.html`을 확장하지 않기 때문에, `{% load i18n %}`을 별도로 선언해야 했다. 또한 `LANGUAGE_CODE`를 사용하여 `<html lang="{{ LANGUAGE_CODE }}">`를 설정하고, 번역된 문자열을 `BattleI18n` 객체에 주입하는 방식을 취했다.

### 4. 번역 누락 탐지

다국어 작업이 진행될수록 새로운 템플릿 문자열이 추가될 때마다 `.po` 파일에 빈 `msgstr ""`이나 fuzzy 항목이 생겼다. 이를 자동으로 감지하는 방법이 없어서, 매번 `makemessages` 후수동으로 확인하고 채워야 했다.

---

## 배운 점

- Django i18n은 3계층(Django 템플릿, Python 코드, JavaScript)으로 분리해서 생각해야 한다. 각 계층에서 번역을 다르게 적용해야 하므로 아키텍처를 처음부터 명확히 설계하는 것이 중요하다.
- `makemessages`는 편리하지만, fuzzy 마커를 자동으로 생성할 수 있으므로 항상 확인이 필요하다. 특히 문자열이 조금만 달라도 Django가 자동으로 fuzzy로 표시한다.
- JavaScript의 다국어는 Django 템플릿에서 직접 주입하는 것이 가장 간단하다. 별도의 JSON 파일을 만들고 AJAX로 로드하는 방식도 가능하지만, 템플릿 렌더링 시점에 이미 언어가 결정되어 있으므로 직접 주입이 더 효율적이다.
