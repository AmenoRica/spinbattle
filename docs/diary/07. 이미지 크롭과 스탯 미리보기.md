# 07. 이미지 크롭과 스탯 미리보기

## 목표

사용자가 이미지를 업로드할 때 1:1 비율로 크롭할 수 있게 하고, 업로드 전에 생성될 스탯을 미리 확인할 수 있는 모달을 제공한다.

---

## 무엇을 만들었나

### Cropper.js 연동

`Cropper.js`(CDN)를 사용하여 이미지 선택 시 크롭 모달이 열리도록 했다.

**흐름**:
1. 사용자가 파일 입력에서 이미지 선택
2. `ImageCropper.showModal(file)`이 호출되어 크롭 모달 표시
3. Cropper 인스턴스 생성 (aspectRatio: 1, viewMode: 1, autoCropArea: 0.9)
4. "크롭 적용" 버튼 클릭 → 512×512 JPEG로 크롭 (quality: 0.92)
5. 크롭 결과를 썸네일로 미리 표시
6. 파일명에서 자동으로 팽이 이름 채움 (확장자 제거, 30자 제한)

### 스탯 미리보기 모달

"업로드" 버튼을 누르면 바로 저장되지 않고, 먼저 `upload_preview` AJAX 엔드포인트로 스탯을 계산한다.

**`upload_preview` 뷰** (`accounts/views.py`):
- POST 요청만 허용
- `SpinImageForm` 검증 후, `commit=False`로 인스턴스 생성
- 해시와 속성 계산 (저장은 하지 않음)
- 개수 제한 검증
- 스탯, 등급, 속성명, 속성색상, 총합을 JSON으로 반환

**모달 UI**:
- 팽이 이름과 속성 뱃지 (색상 포함)
- 6개 스탯 막대 (값, 등급, 등급 색상)
- 총합 표시
- "취소" 또는 "확인" 버튼

"확인"을 누르면 실제 `upload_image` 엔드포인트로 FormData를 전송하여 저장한다.

## 어떤 문제를 겪었나

### 1. `upload_preview`와 `upload_image`의 분리

처음에는 하나의 뷰에서 두 가지 역할(미리보기 + 저장)을 처리하려고 했다. 하지만 미리보기에서는 저장하지 않고 스탯만 반환해야 하고, 실제 저장에서는 스탯을 다시 계산할 필요가 없으므로(이미 계산됨), 두 뷰로 분리하는 것이 명확했다.

미리보기 뷰에서 `form.save(commit=False)` 후 `full_clean()`을 호출하여 검증하지만 저장하지는 않는다. 실제 저장은 확인 버튼을 눌렀을 때 `upload_image` 뷰에서 수행한다.

### 2. FormData 재구성

"확인" 버튼을 눌렀을 때 크롭된 Blob을 File 객체로 변환하여 기존 FormData의 이미지 필드를 덮어써야 했다. `fd.set("image", croppedFile, croppedFile.name)`으로 해결했다.

### 3. CSRF 토큰

AJAX 요청에 CSRF 토큰이 필요했다. 미리보기 요청은 FormData에 `{% csrf_token %}`으로 포함된 토큰이 자동으로 들어가므로 별도 처리가 필요 없었다.

## 배운 점

- 이미지 크롭은 사용자 경험을 크게 개선한다. 팽이(원형) 이미지에 1:1 비율로 크롭하면 속성 색상 계산도 더 정확해진다.
- "저장 전 미리보기" 패턴은 게임에서 특히 유용하다. 사용자가 업로드 전에 스탯을 확인할 수 있으므로, 기대와 다른 결과가 나왔을 때 즉시 다른 이미지를 시도할 수 있다.
- FormData의 `set()` 메서드는 기존 필드를 덮어쓴다. `append()`는 같은 이름의 필드를 추가하므로 주의해야 한다.
