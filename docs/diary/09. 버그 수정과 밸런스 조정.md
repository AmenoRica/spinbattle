# 09. 버그 수정과 밸런스 조정

## 목표

개발 과정에서 발견한 버그를 수정하고, 게임 밸런스와 UI 디테일을 개선한다.

---

## 어떤 문제를 겪었나

### 1. 강철 타입 과다 문제

**문제**: 업로드된 이미지의 속성이 강철(steel)로 편중되는 현상이 발생했다.

**원인 분석**: `compute_type_from_image()`에서 채도 기준값이 `s < 0.12`로 너무 높았다. 대부분의 실사 이미지는 평균 채도가 0.05~0.20 사이여서, 0.12 이하인 이미지가 많았고 이들이 모두 "강철" 또는 "얼음"으로 분류되었다. 또한 예외 처리 시에도 항상 `"steel"`을 반환하여 문제가 악화되었다.

**해결**:
- 채도 기준값을 `0.12` → `0.06`으로 낮추어 정말로 무채색인 이미지만 강철/얼음으로 분류
- 명도 기준값을 `0.2` → `0.15`으로 조정
- 전구 색상(Hue) 범위를 약간 조정 (Yellow: 70→75)
- 예외 처리 시 고정 `"steel"` 대신 랜덤 속성 반환

**검증**: 20가지 대표 색상으로 테스트한 결과, 강철은 진짜 회색 건물 이미지(1개)에만 할당되고, 은색 금속은 채도 0.103로 새 기준을 통과하여 water로 분류되었다. 전체 분포가 훨씬 균등해졌다.

### 2. `{% load i18n %}` 위치 에러

**문제**: `battle_friendly.html`에서 접속 시 `TemplateSyntaxError: Invalid block tag on line 6: 'trans'` 에러가 발생했다.

**원인**: `{% load i18n static %}`가 `{% trans "대전" %}`보다 뒤(8번째 줄)에 있었다. Django 템플릿은 `{% load %}`가 같은 파일에서 해당 태그를 사용하기 전에 선언되어야 한다.

**해결**: `{% load i18n static %}`을 파일 최상단(`<!DOCTYPE html>` 이전)으로 이동했다.

### 3. `.po` 파일의 fuzzy 마커로 인한 번역 무시

**문제**: "시작!" 문자열이 일본어와 영어에서도 한국어로 표시되었다.

**원인**: `makemessages`가 유사한 기존 문자열("시작하기")과 연관지어 `#, fuzzy` 마커를 자동으로 추가했다. fuzzy 마커가 있으면 Django는 해당 번역을 무시하고 원문(msgid)을 그대로 출력한다.

**해결**: 모든 `.po` 파일에서 `#, fuzzy` 마커와 `#| msgid` 참조 줄을 제거하고, 빈 `msgstr`을 올바른 번역으로 채웠다. 이후 `makemessages`를 실행할 때마다 fuzzy 마커가 다시 생길 수 있으므로 매번 확인이 필요하다.

### 4. 한국어 하드코딩 이펙트 텍스트

**문제**: 전투 중 "가속!"과 "인내!"가 언어 설정과 상관없이 항상 한국어로 표시되었다.

**원인**: `battle-effects.js`에 `"가속!"`, `"인내!"`이 하드코딩되어 있었다.

**해결**: `BattleI18n.accel`과 `BattleI18n.endure`를 참조하도록 변경했다. `BattleI18n` 객체는 `battle_friendly.html`에서 `{% trans %}`로 렌더링되어 언어에 따라 다른 번역 문자열을 가진다.

### 5. 상단바 순서와 디자인

**문제**: 상단바의 요소 순서가 직관적이지 않았다. 유저 목록과 랭크 대전 버튼 사이에 언어 선택기와 인사말이 있어 흐름이 끊겼다.

**해결**: 왼쪽에 내비게이션(로고 → 유저 목록 → 업로드 → 랭크 대전), 오른쪽에 사용자 영역(언어 선택 → 사용자 이름 → 로그아웃)으로 재구성했다. "반갑습니다" 인사말은 제거하고 사용자 이름만 프로필 링크로 표시했다.

### 6. 팽이 크기와 이펙트 스케일

**문제**: 전투 페이지에서 이펙트(스파크, 베기, 부유 텍스트)가 팽이에 비해 너무 작게 보였다.

**해결**: 팽이 크기를 350px로 고정하고, 이펙트 크기를 스케일업:
- 스파크: 6px→10px, 이동거리 30-70px→50-120px, 개수 증가
- 베기 이펙트: 70px→120px, 두께 3px→5px (크리티컬 5px→8px)
- 부유 텍스트: 14px→22px, 이동거리 증가
- 글로우/오라 반경 증가
- 공격 돌진 거리: 30px→50px

### 7. 전투 페이지 접속 불가

**문제**: `/battle/` 페이지 접속 시 전과 동일한 `TemplateSyntaxError`가 발생했다.

**원인**: 이전 수정에서 `{% load i18n static %}`를 `<head>` 내부로 이동했지만, 여전히 `{% trans %}`보다 뒤에 있었다. `{% load %}`는 `{% trans %}`가 사용되기 전에 반드시 실행되어야 한다.

**해결**: `{% load i18n static %}`을 `<!DOCTYPE html>` 바로 앞(파일 최상단)으로 이동하여 해결했다.

### 8. `upload_image` 뷰 소실

**문제**: `upload_preview` 뷰를 추가하는 과정에서 `upload_image` 뷰가 소실되어 `AttributeError: module 'accounts.views' has no attribute 'upload_image'` 에러가 발생했다.

**원인**: `upload_preview` 함수를 `upload_image` 함수 정의 앞에 삽입할 때, `upload_image`의 본문이 `upload_preview`의 `return` 이후에 unreachable 코드로 남아 있었다.

**해결**: `upload_image` 뷰를 `upload_preview` 다음에 올바르게 별도의 함수로 정의했다.

---

## 배운 점

- Django 템플릿에서 `{% load %}`의 위치는 매우 중요하다. 같은 파일 내에서 load보다 태그 사용이 먼저 오면 에러가 발생한다. 특히 독립형 페이지(base.html을 확장하지 않는 템플릿)에서는 항상 파일 최상단에 load를 두어야 한다.
- `.po` 파일의 `fuzzy` 마커는 의도치 않게 번역을 무시하게 만든다. `makemessages` 후에는 반드시 fuzzy 항목을 확인하고 수동으로 수정해야 한다.
- 게임 밸런스의 "형평성"은 수치 기준 하나로 크게 달라질 수 있다. 강철 타입 편중 문제는 채도 임계값(e 0.12→0.06) 하나의 조정으로 해결되었지만, 이를 발견하기 위해서는 실제 데이터(업로드된 이미지들의 속성 분포)를 확인하는 과정이 필요했다.
- 코드 삽입 시 함수 경계를 명확히 확인해야 한다. `return` 이후의 코드가 unreachable이 되지 않도록 주의해야 한다.
