# 11. Bulk Upload 기능 추가

## 목표

유저가 부족한 상황에서 중립(시스템) 팽이 이미지를 쉽게 추가할 수 있도록, Django admin에 대량 업로드 기능을 만든다. 또한 시스템 유저가 유저 목록에 노출되지 않도록 숨김 처리한다.

---

## 무엇을 만들었나

### SpinImage 어드민 등록 (`accounts/admin.py`)

기존에는 `SpinImage`가 어드민에 등록되어 있지 않았다. `SpinImageAdmin`을 추가하여 `name`, `user`, `spin_type`, `battle_score` 등을 목록에서 볼 수 있게 했다.

### 대량 업로드 뷰

어드민의 SpinImage 목록 페이지에 **"대량 업로드"** 버튼을 추가하고, 커스텀 뷰(`/admin/accounts/spinimage/bulk-upload/`)를 만들었다.

- **유저 선택**: 어떤 유저의 이미지로 등록할지 선택
- **이름 접두사**: 입력하면 `{접두사}_1`, `{접두사}_2` 형식으로 이름 생성. 비워두면 파일명에서 추출
- **다중 파일 선택**: 여러 이미지를 한 번에 업로드
- **처리 로직**:
  - 5MB 초과 → 스킵
  - 해시 중복 → 스킵
  - 정상 → `SpinImage.objects.create()`로 생성 (hash, spin_type 자동 계산)
  - `clean()` 호출하지 않고 직접 `create()` → MAX_PER_USER 제한 우회

### BulkSpinImageForm (`accounts/forms.py`)

유저 선택과 이름 접두사만 포함하는 폼. 파일은 템플릿에 직접 `<input type="file" multiple>`을 작성하고, 뷰에서 `request.FILES.getlist("images")`로 직접 처리한다.

### 숨겨진 유저 (`is_hidden` 필드)

`CustomUser`에 `is_hidden = BooleanField(default=False)`을 추가하고, `user_list` 뷰에서 `is_hidden=False` 필터를 적용했다. 어드민 유저 편집 페이지에서 체크박스로 설정 가능.

---

## 어떤 문제를 겪었나

### 1. Django 5.x에서 `FileInput`의 `multiple` 속성 차단

**문제**: 대량 업로드 폼에서 `multiple` 속성이 있는 파일 입력을 만들려고 `forms.FileInput(attrs={"multiple": True})`를 사용했더니 `ValueError: FileInput doesn't support uploading multiple files` 에러가 발생했다.

**원인**: Django 5.x의 `FileInput.__init__`이 `self.allow_multiple_selected` 속성을 검사해서, `False`인 경우 `attrs`에 `multiple`이 있으면 에러를 발생시킨다.

**시도 1**: `ClearableFileInput`을 상속하고 `allow_multiple = True`를 설정 → 여전히 같은 에러. 속성 이름이 `allow_multiple_selected`였다.

**시도 2**: `allow_multiple_selected = True`로 설정하고 `__init__`에서 `attrs["multiple"] = True`를 추가 → `super().__init__()`에서 다시 에러. 부모 `__init__`이 `multiple` 속성을 검사하는 시점이 문제였다.

**해결**: 결국 폼에서 파일 필드를 아예 빼고, HTML 템플릿에 직접 `<input type="file" name="images" accept="image/*" multiple>`을 작성했다. 뷰에서는 `request.FILES.getlist("images")`로 파일 목록을 직접 받아서 처리한다. Django의 폼 위젯 시스템보다 HTML 직접 작성이 다중 파일 업로드에서는 훨씬 간단하다는 걸 배웠다.

### 2. `MAX_PER_USER=3` 제한 우회

**문제**: `SpinImage.clean()`에서 유저당 최대 3개 제한을 검사한다. 시스템 유저에 대량으로 이미지를 올리려면 이 제한을 우회해야 한다.

**해결**: `SpinImage.objects.create()`는 `full_clean()`을 호출하지 않으므로, `clean()` 검증을 건너뛴다. `hash`와 `spin_type`은 `save()`에서 자동 계산되지만 `create()`도 내부적으로 `save()`를 호출하므로 정상적으로 계산된다.

### 3. 중복 이미지 에러 처리

**문제**: 같은 이미지를 두 번 업로드하면 `hash` 필드의 `unique=True` 제약으로 `IntegrityError`가 발생할 수 있다.

**해결**: 업로드 전에 해시를 계산하고 `SpinImage.objects.filter(hash=file_hash).exists()`로 먼저 검사해서 중복이면 스킵한다. 이때 `f.seek(0)`로 파일 포인터를 리셋하는 것을 잊으면 `compute_type_from_image()`가 빈 파일을 읽게 되므로 주의가 필요했다.

### 4. 일반 사용자의 중복 이미지 업로드 차단

**문제**: 일반 사용자가 같은 이미지를 두 번 업로드하면 `hash` unique 제약으로 500 에러가 발생했다. 기존에는 검증이 없었다.

**해결**: `upload_preview`와 `upload_image` 두 뷰 모두에 해시 중복 체크를 추가했다. `upload_preview`는 JSON 400 에러로, `upload_image`는 폼 에러로 처리한다.

## 배운 점

- **Django admin 커스텀 뷰**: `ModelAdmin.get_urls()`로 커스텀 URL을 추가하고, `admin_site.admin_view()`로 권한 체크를 유지하는 패턴을 배웠다. `change_list_template`으로 목록 페이지에 버튼을 추가하는 방법도 유용했다.
- **`objects.create()`와 `full_clean()`의 차이**: `create()`는 `save()`를 호출하지만 `full_clean()`은 호출하지 않는다. 이 덕분에 어드민 대량 업로드에서 per-user 제한을 우회할 수 있었다. 하지만 이는 의도된 동작이므로 일반 사용자 뷰에서는 여전히 `clean()` 검증이 적용된다.
- **다중 파일 업로드의 정석**: Django 폼 위젯으로 다중 파일을 처리하려면 위젯 클래스부터 까다롭다. HTML을 직접 작성하고 `request.FILES.getlist()`로 처리하는 것이 오히려 깔끔한 해결책이 될 수 있다.
- **해시 기반 중복 검사**: 이미지의 SHA-256 해시를 이미 `SpinImage` 모델에서 자동 계산하고 있으므로, 이를 활용해 중복 업로드를 O(1)으로 검사할 수 있다. 5MB 파일의 해시 계산은 사용자 체감상 거의 무시할 수준이다.
