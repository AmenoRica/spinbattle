# 12. 전투 밸런스 리밸런싱 & 프로필/업로드 통합

## 목표

전투 스탯 간 밸런스를 분석하고, 과도하게 강력한 스탯을 조정하며, 약한 스탯의 효용을 높인다. 또한 프로필 페이지와 업로드 페이지를 "내 팽이" 단일 페이지로 통합한다.

## 전투 밸런스 분석

### 문제 진단

5,000회 몬테카를로 시뮬레이션 결과, 스탯 간 승률 상관관계가 극심하게 불균형했다:

| 스탯 | 높은 쪽 승률 | 문제 |
|---|---|---|
| **speed** | **74.3%** | 속도=체력+선공+데미지 배수 → 압도적 1위 |
| **luck** | **63.7%** | 크리, 우선권, 이벤트 모두에 영향 |
| **stamina** | 56.6% | 감속 저항 → 적절 |
| **attack** | 53.0% | speed 곱연산 때문에 한계효용 낮음 |
| **acceleration** | 52.8% | 가속 이벤트 확률 낮고 효과 미미 |
| **defense** | **40.6%** | **역상관** (방어가 높으면 짐!) |

#### 근본 원인

1. **speed가 HP 겸 공격 배수**: 데미지 공식이 `speed × attack / 500`이라 속도가 높으면 공격력도 같이 곱해짐. 게다가 속도=체력이라 속도 하나로 3가지 효과
2. **defense가 아무 효과 없음**: 감속 계산에 방어가 전혀 관여하지 않고, 데미지 방어도 `% 감소`라 속도가 높을수록 절대값이 커서 무의미
3. **선제 판정이 speed 단일**: luck 변동이 있긴 하지만 기본이 speed 단독이라速度 높은 쪽이 항상 먼저 때림
4. **luck 영역 과다**: 크리, 우선권 랜덤, 랜덤 이벤트 가중치, 가속 발동 확률 등 4가지 시스템에 영향

### 해결: 공식 전면 수정

#### 1. 데미지 공식: 승산→가산

```
이전: base_damage = (speed × attack) / 500
이후: base_damage = attack × 0.18 + speed × 0.02
```

speed와 attack을 곱하지 않고 더하여, speed는 전체 데미지에 작은 기여만 하도록 변경. attack을 독립적인 데미지 원천으로 만듦.

#### 2. 초기 HP에 defense 기여

```
이전: initial_speed = speed
이후: initial_speed = speed + defense × 0.4
```

defense가 높으면 체력이 늘어남. 방어 60이면 speed + 24만큼 HP 보너스.

#### 3. 방어 감소율 강화

```
이전: reduction = def / (def + 100)   → def 60일 때 37.5% 감소
이후: reduction = def / (def + 35)    → def 60일 때 63.2% 감소
```

분모를 35로 낮추어 defense의 피해 감소 효과를 대폭 강화.

#### 4. 감속에 defense 관여

```
이전: decel = 3.0 × (100 / stamina) × growth
이후: decel = 4.0 × (80 / stamina) × growth × max(1 - defense × 0.008, 0.3)
```

defense가 높을수록 감속이 줄어듦 → 더 오래 회전 = 더 오래 버틴다. defense 60이면 감속이 52% 감소함.

#### 5. 선제 판정 다원화

```
이전: priority = speed ± luck × 0.5
이후: priority = speed × 0.6 + attack × 0.25 + defense × 0.15 ± luck × 0.3
```

speed 단일 판정에서 attack/defense도 선제에 기여하도록 변경. luck 변동폭도 축소.

#### 6. 크리티컬 확률 하향

```
이전: 0.05 + luck × 0.003    → luck 100일 때 35% 확률
이후: 0.05 + luck × 0.0015   → luck 100일 때 20% 확률
```

luck의 영향력 축소.

#### 7. 기타 조정

| 항목 | 이전 | 이후 | 효과 |
|---|---|---|---|
| 크리 배율 | `1.5 + accel/200` | `1.5 + accel × 0.01` | acceleration의 크리 배율 기여 유지 |
| 가속량 | `5 × √accel` | `6 × √accel` | acceleration의 가속 효과 약간 상향 |
| 기본 감속 | 3.0 | 4.0 | 전투 길이 단축 |
| 지구력 감속 계수 | 100 | 80 | 전투 길이 단축 |

### 결과

5,000회 몬테카를로 시뮬레이션 (수정 후):

| 스탯 | 이전 승률 | 이후 승률 | 변화 |
|---|---|---|---|
| speed | 74.3% | 63.0% | -11.3%p |
| luck | 63.7% | 56.6% | -7.1%p |
| stamina | 56.6% | 43.7% | -12.9%p |
| attack | 53.0% | 49.0% | -4.0%p |
| acceleration | 52.8% | 49.9% | -2.9%p |
| defense | 40.6%(역) | 47.0% | +6.4%p |

모든 스탯이 43~63% 범위 내에서 영향을 미치며, defense의 역상관이 해소됨. 평균 전투 길이 10턴, 최소 1턴~최대 25턴.

## 프로필/업로드 통합 ("내 팽이" 페이지)

### 변경 내용

- `profile` 뷰 + `upload_image` 뷰 → `my_spins` 뷰로 통합
  - `form_type` hidden 필드로 프로필 저장과 업로드를 구분
- URL: `/accounts/profile/` + `/accounts/upload/` → `/accounts/my_spins/`
- 템플릿: `profile.html` + `upload.html` → `my_spins.html`
  - 상단: 프로필 수정 폼 (유저네임, 이메일, 소개)
  - 중간: 팽이 업로드 폼 (5개 미만일 때만 표시)
  - 하단: 내 팽이 목록 (랭크 점수 내림차순)
- 네비게이션: "이미지 업로드" → "내 팽이", 홈 "프로필" → "내 팽이"
- 최대 업로드: 3개 → 5개로 상향

## 배운 점

- **곱셈 공식의 위험성**: `speed × attack` 같은 곱셈 공식은 한 변수가 높으면 다른 변수의 한계효용도 높아져 불균형이 급격히 악화된다. 가산 공식(`attack + speed`)은 각 변수의 독립적 기여를 보장한다.
- **역상관의 원인**: defense가 아무 효과가 없다는 것은 "defense에 투자한 스탯 포인트가 다른 스탯에 갔어야 했다"는 뜻이다. 즉 방어가 높은 팽이는 다른 스탯이 낮아서 지는 것. 해결하려면 defense가 실제로 생존에 기여하게 만들어야 한다 (HP 보너스, 감속 감소, 데미지 감소율 강화).
- **몬테카를로 검증**: 공식 변경 후 반드시 시뮬레이션으로 스탯별 승률 상관관계를 검증해야 한다. 직관과 실제 결과가 다를 수 있다.
- **선제 판정 다원화**: speed 단일 판정은 speed의 가치를 과대평가하게 만든다. attack과 defense도 선제에 기여하게 하면 다른 스탯의 가치가 올라간다.
