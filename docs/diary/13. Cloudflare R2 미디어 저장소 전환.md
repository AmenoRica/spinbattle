# 13. Cloudflare R2 미디어 저장소 전환

## 목표

기존 로컬 `media/` 저장 방식에서 벗어나, 이미지 파일을 Cloudflare R2에 저장하도록 전환한다. 서버 디스크 부담을 줄이고 운영 안정성을 높이며, 기존 업로드 파일도 안전하게 이관한다.

---

## 변경 내용

### 1) 스토리지 전환 토글 추가

- `spinbattle/settings.py`에 `USE_R2_STORAGE` 환경변수 기반 분기 추가
- `USE_R2_STORAGE=True`일 때:
  - `storages` 앱 활성화
  - S3 호환 `STORAGES["default"]` 설정
  - `R2_ACCOUNT_ID`, `R2_BUCKET_NAME`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` 필수 검증
  - `R2_ENDPOINT_URL` 지원(입력값에 버킷 경로가 있어도 host-only로 정규화)
  - `R2_PUBLIC_URL` 설정 시 `MEDIA_URL` 전환

### 2) 의존성 추가

- `requirements.txt`
  - `django-storages`
  - `boto3`

### 3) 삭제 동기화 보완

- `accounts/models.py`의 `SpinImage.delete()`에서 스토리지 파일도 함께 삭제
- DB 레코드만 지워지고 파일이 남는 누수 문제를 방지

### 4) 기존 파일 이관 커맨드 추가

- `accounts/management/commands/migrate_media_to_r2.py`
- 기능:
  - 로컬 `MEDIA_ROOT` 기준 파일 존재 확인
  - 현재 default storage(R2)에 업로드
  - `--dry-run`, `--limit` 지원
- `dry-run`은 네트워크 의존 호출 없이 로컬 기준 점검 가능하도록 구성

### 5) 운영 문서/예시 정리

- `.env.example` 추가
- `README.md`에 R2 설정 및 이관 절차 추가
- `.gitignore`에 `!.env.example` 예외 추가 (`.env`는 계속 ignore)
- `AGENTS.md`에 R2 구조/커맨드 반영

---

## 장애 대응 기록

초기에는 R2 endpoint 연결에서 TLS 핸드셰이크 실패가 발생했다:

- 에러: `SSLV3_ALERT_HANDSHAKE_FAILURE`
- 재현:
  - `boto3` 업로드 시 실패
  - `openssl s_client` TLS 1.2/1.3 강제 테스트에서도 실패

이후 일정 시간이 지나 동일 endpoint 재시도 시 정상 복구되었고,

- TLS 검증 성공
- 실제 업로드 성공

즉 애플리케이션 코드 자체보다는 Cloudflare endpoint 상태/프로비저닝 타이밍 이슈 가능성이 컸다.

---

## 마이그레이션 결과

실행 순서:

1. `python manage.py migrate_media_to_r2 --dry-run`
2. `python manage.py migrate_media_to_r2`
3. 재실행으로 중복 업로드 여부 확인

결과:

- 대상: 20
- 업로드: 19
- 건너뜀: 1 (사전 테스트 업로드 1건)
- 누락: 0

최종 재검증:

- 대상: 20
- 업로드: 0
- 건너뜀: 20
- 누락: 0

현재 DB 기준 이미지 파일은 전부 R2에 존재한다.

---

## 배운 점

- 스토리지 전환은 코드보다 운영 변수(키/엔드포인트/권한/인증서 상태)의 영향이 크다.
- `dry-run`은 네트워크/권한 장애 상황에서 안전하게 준비 상태를 검증하는 데 매우 유용하다.
- 파일 삭제 동기화 로직은 저장소 전환 시 반드시 함께 넣어야 장기 운영에서 누수가 줄어든다.
